GShare
문제 핵심 기능 동작 방식 아키텍처 역할
Kubernetes GPU Sharing Platform

하나의 GPU 클러스터를
조직 전체가 나눠 씁니다

GShare는 여러 조직·부서·사용자가 하나의 GPU 클러스터를 분할(fractional)·전용(exclusive)으로 나눠 쓰고, 크레딧으로 과금·관리하는 GPU 공유 플랫폼입니다. GPU를 직접 쪼개는 대신, 그 위에서 누가·얼마나·어떤 비용으로 쓰는지를 책임지는 제어 영역입니다.

왜 필요한가

GPU는 비싼데, 늘 누군가는 놀고 있습니다

전용 할당은 단순하지만 활용률이 낮고, 단순 분할은 비용·한도·회수를 통제하지 못합니다. GShare는 분할 기술(HAMi) 위에서 운영 문제를 해결합니다.

🔻 기존 방식의 한계

  • 1인 1카드 전용 할당 → 점유 시간 대부분 GPU 유휴
  • 단순 time-slicing/분할은 비용 귀속·한도 관리가 없음
  • 유휴 세션이 카드를 붙잡아 대기열만 길어짐
  • 부서·조직별 예산 통제와 감사 추적이 어려움
  • 큰 작업이 들어갈 빈 카드가 조각나 사라짐(단편화)

🔼 GShare의 접근

  • 분할(fractional)·전용(exclusive)을 한 클러스터에서 혼용
  • 점유율(occupancy) 기반 과금 — 쓴 만큼 크레딧 차감
  • 유휴 GPU는 자동 일시정지로 즉시 회수, 작업은 보존
  • 계층 크레딧·예산 게이트·자원 정책으로 한도 관리
  • 점유율을 고려한 bin-packing으로 빈 카드 보존
핵심 기능

분할 위에 얹은 운영 지능

실제 GPU 분할은 HAMi와 전용 풀카드가 맡고, GShare는 그 위에서 배치·과금·회수를 통합합니다.

🧩

점유율을 고려한 bin-packing

VRAM·코어 두 축의 잔여를 함께 보는 best-fit 배치. 가장 꽉 차는 카드로 통합해 빈 카드를 보존하고, 전용·대형 작업 수용력을 지킵니다. spread 정책도 토글 제공.

구현 완료
⏸️

유휴 자동 일시정지

유휴(util≈0) GPU 세션을 종료가 아닌 자동 일시정지로 회수합니다. 파드를 내려 물리 GPU를 반환하되 세션·볼륨·크레딧은 보존, 사용자는 언제든 재개합니다.

구현 완료
💾

무손실 일시정지

체크포인트(cuda-checkpoint + CRIU)로 GPU 메모리 상태를 보존한 채 카드를 반환하고, 재개 시 상태 그대로 복원합니다. 모델 재로딩 비용 없는 회수.

설계 단계
💳

계층 크레딧 · 예산

시스템→조직→부서→개인으로 크레딧을 배분하고, 세션은 본인 지갑에서만 과금. 범위별 예산 게이트로 초과를 차단/경보하고 월 자동 리필을 지원합니다.

구현 완료
📐

자원 정책 · 한도

동시 실행 수, 자원 총량, 유휴 타임아웃을 정책으로 통제. 사용자→부서→조직→공통 순으로 해석해 조직마다 다른 운영 규칙을 적용합니다.

구현 완료
🖥️

대화형 세션

VSCode·JupyterLab·웹터미널을 1회용 링크로 즉시 접속. 대기열·우선순위 자동 배정, 볼륨/스냅샷, 감사 로그까지 콘솔 한 곳에서.

구현 완료
동작 방식

세션 생성 한 번에 일어나는 일

요청은 허용 검사를 순서대로 통과해야 기동되고, 그때부터 점유율 기반 과금이 시작됩니다.

STEP 1

선택

오퍼링(GPU 모델·티어)·이미지·볼륨을 고르면 예상 크레딧을 표시.

STEP 2

허용 검사

정책 한도 → 예산 → 크레딧 hold → 점유율을 고려한 VRAM 예약 순으로 통과.

STEP 3

기동

제어 영역이 CR 적용 → operator가 파드/서비스/인그레스 생성.

STEP 4

과금·회수

running 콜백부터 과금 시작, 유휴 시 자동 일시정지로 GPU 반환.

아키텍처

제어 영역 · 실행 영역 분리

돈과 상태 결정은 제어 영역(backend)이 책임지고, 실제 쿠버네티스 실행은 클러스터별 operator가 맡습니다. 제어 영역은 kubeconfig로 외부 GPU 클러스터에도 세션을 적용할 수 있습니다.

  사용자 / 관리자
      │ 브라우저
      ▼
  콘솔 (frontend, React SPA)            ── 사용자·관리자 화면 (REST/SSE)
      │ REST/SSE
      ▼
  제어 영역 (backend, FastAPI)          ── 상태·돈의 중심: 인증·권한, 크레딧/예산,
      │  ├ gshare-api    세션 허용 검사·CRUD·토큰         카탈로그/정책, 스케줄링
      │  └ gshare-worker  과금·예산 롤업·대기열·리필
      │ GShareSession CR 적용 (kubeconfig)      ▲ 서명된 상태/인벤토리 콜백 (내부 JWT)
      ▼                                         │
  operator (Go, 클러스터별) ──▶ Pod / Service / Ingress (gshare-sessions ns)
      │                                  세션 파드 = 대화형 환경(VSCode/Jupyter/터미널)
      ▼
  HAMi + GPU 노드                       ── 실제 GPU 분할(gpumem/gpucores) · 전용 풀카드

  postgres(상태·원장) · redis(큐·토큰·락)
분할 메커니즘은 HAMi(분할 vGPU)·전용 풀카드에 위임하고, GShare는 그 위에서 점유율 기반 배치·과금·유휴 회수를 통합 관리합니다.
