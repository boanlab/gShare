# GShare cluster operator

A controller-runtime operator in the kubebuilder v4 layout — GShare's **Kubernetes
execution plane**. It reconciles the `GShareSession` custom resources that the Python
control plane applies into pods, services, ingresses, and secrets, and reports status back
over a signed internal callback.

- API group `gshare.io`, version `v1`, kind `GShareSession`
- Go 1.22 · sigs.k8s.io/controller-runtime · client-go
- Module `github.com/gshare/operator`

## Design

- **CRD-primary.** The control plane applies the custom resource; the operator owns the
  lifecycle of its children through owner references and a finalizer, and writes `.status`.
- **Status synchronisation is a signed callback** — `POST /internal/sessions/{id}/status`,
  authenticated with a short-lived RS256 internal JWT (`aud=gshare-internal`), never a user
  key. The operator only holds the token; the control plane holds the private key and
  verifies against its internal JWKS. **The operator never touches credits** — money is the
  control plane's business.
- **Operator audit.** Cordon, drain, and pod deletion are reported to
  `POST /internal/audit/operator`.
- **Pod shape per mode**, as dictated by the control plane:
  - `fractional` — `runtimeClassName: nvidia`, `nvidia.com/gpumem` and
    `nvidia.com/gpucores`, scheduled by `hami-scheduler`.
  - `exclusive` — the standard device plugin's `nvidia.com/gpu: 1`, bypassing
    `hami-scheduler` entirely.
  - `cpu` — `nodeSelector gshare.io/node-type=cpu`, no GPU, free of charge.
  - MIG is not supported. The control plane rejects `mig`, so it never reaches the operator.
- **Pause and resume.** With `spec.paused=true` the operator deletes the pod, **returning
  the physical GPU**, and reports `status.phase=Paused` — this is not termination. Setting
  it back to `false` recreates the pod. The custom resource survives throughout.
- The per-session secret `ses-<id>-secret` is projected from `spec.connect`.
- No API keys, no batch. Status callbacks carry a `trace_id` in W3C `traceparent` form.

## Layout

```
api/v1/                GShareSession types and generated deepcopy
cmd/main.go            manager bootstrap, flags, controller registration
internal/controller/   SessionReconciler (reconcile loop, finalizer) and the envtest suite
internal/podbuilder/   BuildPod (per mode), BuildSecret, BuildService, BuildIngress
internal/sot/          control-plane client: Report() and AuditOperator() (RS256 bearer, trace_id)
internal/health/       xid and ECC errors → cordon → NodeHealthEvent + audit
internal/inventory/    node and GpuDevice inventory → control plane
internal/reaper/       idle GPU → pause (spec.paused); max runtime or idle CPU → terminate + audit
internal/checkpoint/   CRIU and cuda-checkpoint driven lossless pause
internal/dcgm/         per-GPU utilisation from DCGM/Prometheus or the HAMi device-plugin monitor
internal/webhook/      lend-guard admission webhook and its self-signed certificate management
config/                CRD, RBAC, manager, samples — all generated by controller-gen
```

Everything under `config/crd` and `config/rbac`, and `api/v1/zz_generated.deepcopy.go`, is
controller-gen output: edit the `+kubebuilder:` markers in the Go source and re-run
`make manifests generate`. CI fails if the committed output is stale.

`config/rbac/role.yaml` is a single coarse ClusterRole for out-of-cluster development
(`make install-rbac`). The deployed permissions are the namespace-scoped Roles in
`charts/gshare/templates/operator-rbac.yaml`, which are the authoritative, least-privilege set.

## Development

```bash
make manifests   # regenerate CRD and RBAC manifests
make generate    # regenerate deepcopy functions
make build       # build the manager binary
make run         # run out-of-cluster against the current kubeconfig
make test        # unit tests plus envtest
```

`make run` starts the manager, installs the controllers and the idle reaper, and watches
`GShareSession`. Apply a sample with `kubectl apply -f config/samples/`.
